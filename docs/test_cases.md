# Test Cases — функциональные и DQ проверки

**Среда:** SQLite, автономный HTML и Streamlit. **Формат:** входные условия → действие → ожидаемый результат. Автоматические тесты: `tests/test_etl.py` (8 сценариев).

| ID | Предусловие и действие | Ожидаемый результат |
|---|---|---|
| TC-01 | CSV без `NSM`; запустить ETL | Понятная ошибка о недостающей колонке; старое DWH не повреждено |
| TC-02 | Повторить timestamp в двух строках | Ошибка `Дубли timestamp` |
| TC-03 | `Usage_kWh = -1` | Ошибка отрицательной энергии |
| TC-04 | `Load_Type = X` | Ошибка неизвестной категории |
| TC-05 | WeekStatus не соответствует календарю | Ошибка согласованности |
| TC-06 | Повторный запуск ETL на том же CSV | Число строк не удваивается |
| TC-07 | Выполнить SQL `SUM(usage_kwh)` в raw и DWH | Расхождение меньше 0.0001 кВт·ч |
| TC-08 | Выбрать один месяц в HTML | KPI и графики используют только этот месяц |
| TC-09 | Выбрать «Maximum Load» | Категория одинакова во всех виджетах |
| TC-10 | Выбрать фильтры без данных в Streamlit | Понятное сообщение, приложение не падает |
| TC-11 | Открыть HTML без интернет-соединения | Графики и фильтры работают локально |
| TC-12 | Загрузить файл UCI `--source uci` | 35 040 фактов, режим отчёта REAL UCI |

## Сверка SQL вручную

```sql
SELECT COUNT(*), SUM(usage_kwh) FROM stg_energy_readings;
SELECT COUNT(*), SUM(usage_kwh) FROM fact_energy_readings;
SELECT COUNT(*), SUM(usage_kwh) FROM vw_energy_enriched;
```

Итоги по энергии и количеству должны совпадать. Дополнительные запросы: `sql/01_analytics.sql`.

## Отчёт о фактически выполненных проверках

В сборке проекта локально выполнялись 8 `pytest` тестов с успешным результатом. HTML-отчёт был успешно сгенерирован. **Ручной браузерный UI-тест** и **загрузка на реальный сервер PostgreSQL** не заявляются проверенными; их следует выполнить при развёртывании проекта на конкретной машине.
